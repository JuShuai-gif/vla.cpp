## 基线采集
run_baseline_profile.py 六项全部 rc=0。MCU 通过 begin/end 标记提取预热后真实 F32 图像、43/42-token 状态提示的一次 predict；1834/4584 个 kernel，480.764/780.948 ms。详细累计、次数、均值、寄存器和共享内存见 MCU基线热点.md 和 mcu-ranking-*.json。Graph OFF 采集干预时间不能等同 Graph ON wall。MSYS kernel 数完全一致，但不同 kernel 重复时间戳导致耗时不可靠，已在解析结果标 timing_valid=false，仅核对调用数。

## 1. F32 图像归一化与 patch 打包
直接上传真实 HWC F32，不做 uint8 往返；kernel 执行与旧 CPU (x-.5)/.5 同顺序的减法、乘2和一次 F16 舍入，直接写 patch-major。输入类型纳入 vision cache key，排除映射输入模式。独立 CPU、新 GPU 与原生 GPU 1/2 视图严格一致。首轮8次 control 482.210/786.417 ms，F32 patch 479.759/783.314 ms，两模型 actions 与历史基线逐元素一致。

## 2. 残差/AdaRMS/GeGLU 与小 GEMM F16 补齐复用
残差保留 F32，归一化直接写 F16 [hidden,64]，有效50列，14列补0；GEMM 识别零偏移前缀 view 并复用完整 padded 源，不再转换/复制。CUSTOM 字节 blob 明确拥有 F32 残差和 F16 norm 的全部内存，无隐藏输入写入；语义常量进入 Graph op_params 快照。覆盖普通 norm、层内 residual+norm、跨层 norm；第二轮补上首步 bias norm 与完整模型 action input linear 的 norm 输出。
GeGLU 保留原 tanh 公式和 FP32 运算，输出直接写 padded F16，删去 down GEMM 的单独 pack。独立测试覆盖 rows=1/17/50/64，旧 GPU→F16、新 GPU及 padding，重复 Graph。
初测 norm 477.542/767.839，GeGLU 476.601/772.393；两项及剪枝评分组合460.862/759.479 ms，均 actions 与基线逐元素一致。

## 3. head_dim=256 真融合 Attention
已实现 MP22 WMMA QK→共享内存 F32 softmax→F16 归一化概率→WMMA AV；不读写全局 scores/probs，支持 mask、尾 tile、动态 nq/nk，独立测试包括 nq=1/17/50/278/518/640、nk超640回退、mask、Graph重放。
第一版保留旧128线程 softmax归约树；denoise 569.595/1219.947 ms，all 661.563/1549.914 ms，明显负收益。pruned all 对基线误差0.000950933（近0.001上限），其他三项逐元素一致，不能采用。第二版并行8行 softmax，减少 block barrier，继续独立和整网验证；其求和次序变化，单独走原精度门限。

## 4. K循环预取、双缓冲、展开
probe-pipeline-{0,1,2,4,8}.cu、20组微基准及真实 QKV/O/GateUp/down 形状；所有 max_abs=0。mode1 在当前片段 MMA 前先加载下一组 A/B，避免改变K累加顺序；mode2/4/8循环展开。真实两模型8次：双缓冲480.069/777.788，unroll4 477.743/772.304，unroll8 479.013/779.597。以 F32 patch 479.759/783.314 为初步对照，unroll4进入组合和交替测试；其余不默认启用。定向 MCU 检查寄存器/共享内存/计算利用率，避免只看单个微基准。

## 额外 MCU 热点：剪枝评分复制
基线 cpy_scalar 共7次21.040ms。将 mean(head16) 后 mean(query256) 改为直接读取原 attention，沿用原16头归约树及32-lane query累加/归约次序；不产生 heads-first 布局及 per-query/transposed 中间张量。独立精确比较旧 GPU，整网评分选择与 actions 一致；剪枝初测467.788ms，相对F32 patch节省约11.97ms；完整模型无此路径。
