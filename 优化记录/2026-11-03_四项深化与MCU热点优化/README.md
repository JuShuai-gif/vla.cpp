# 四项深化与 MCU 热点优化

起点 bca90f3。四个方向均已实现和实测，失败原型保留，默认仅采用验证有效的配置。本次只在服务器记录和提交，未同步 Mac。

## 结论与主基准
M1000/MP22，performance，4线程，Graph ON；真实双摄像头 F32 resize 图像、机械臂 state 编入 task prompt，剪枝43 / 完整42 token；50×7 action，保持3 / 10去噪步。计时为权重驻留后的 predict wall（含绑定、输入上传、三部分计算及动作回传），不含权重加载、图片解码/resize/tokenizer。GPU参考0.001、CPU参考0.005门限未变，最终240次测量的动作均与GPU参考逐元素一致。

同一最终二进制按 A B C D D C B A 对称顺序；每段预热3、测15次，各配置/模型30次。所有时长为普通运行，未开 MCU/MSYS。

## 四项逐条实施
1. F32 HWC归一化 + patch + F16打包：直接上传非量化F32图像，用与旧路径相同的数学顺序写patch；输入格式进入vision cache key，1/2视图和格式轮换重建正确。
2. AdaRMS/残差/激活与GEMM补齐复用：保留FP32残差/规约，直接写已有GEMM所需F16 [hidden,64]，补0列14。层内、跨层、首步bias及action input linear均覆盖；GeGLU原公式直接写pad。GEMM只复用零偏移前缀view，其余仍复制/补齐。I8 tensor仅用作混合字节容器，里面存F32/F16数据，未做INT8/FP8/FP4量化。
3. 256维真融合Attention：两个WMMA QK→共享内存softmax→AV版本已独立和整模型实测，未读写全局scores/probs。两版均明显负收益；并行softmax的pruned all误差0.001004323超过原门限，已拒绝。第一版pruned all虽过样例门限，误差0.000950933接近上限，且更慢，不采用。已从生产源码移除；实验源码、完整补丁、命令、结果保留，可在独立bca90f3副本复现。
4. 小GEMM K循环预加载/双缓冲/展开：已测寄存器双缓冲及展开2/4/8的20组微基准；双缓冲、展开4/8分别跑两个模型。MCU定向采集12组真实GEMM形状，发现不同形状的寄存器/吞吐不同；最终D仅GateUp [8192,50,1024]不展开，其余既有小GEMM展开4；保持K累加顺序，FP16输入、FP32累加/输出。未采用方案已从生产路径移除。

## 由MCU推动的额外改动
剪枝模型7次cpy_scalar累计21.040ms。新增直接attention评分规约，不再生成heads-first/per-query/transposed中间张量；保留原16-head及32-lane query归约次序。正弦生成的浮点夹具与旧GPU严格一致；整模型选token及动作一致。完整模型无此剪枝路径。

MCU基线真实推理：剪枝1834个kernel，累计480.764ms；完整4584个kernel，累计780.948ms。排行、调用数、均值、寄存器和共享内存见 [MCU基线热点.md](MCU基线热点.md)，完整排行在 mcu-ranking-*.json。大GEMM仍为主要耗时，剪枝约221.299ms/64次、完整约307.993ms/88次；pruned原生prefix Attention 51.590ms/17次；完整smallGEMM合计169.358ms/720次。

MCU仅用于kernel分析，不将 profiler 下整网wall当成普通延迟；MSYS即使Graph OFF也有重复时间戳/时长，所有结果标 timing_valid=false，仅用于调用计数。warm begin/end标记提取预热后一次predict。C候选的定向MCU为380 / 1250个被过滤kernel，不是整网数量，见 mcu-hot-*.json；不能把其过滤累计与基线整网累计对比。
