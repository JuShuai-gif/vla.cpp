# 06 最终复测与使用说明

## 结论

本轮完成向量化布局转换、可选 muDNN 视觉 Attention、视觉 QKV 合并、可选输入缓存和异步搬运。
保留原 GemmEx：22种真实形状的 muBLASLt 候选均没有收益。前缀/动作 head_dim256 的 muDNN API 返回 NOT_SUPPORTED。
优化模式使用 F16 权重、F32 逻辑激活，内部 GEMM 输入和视觉 SDPA 使用 FP16；不是全 F32 计算，也没有 FP4 量化。
SDPA、视觉 QKV 和输入缓存仍需显式开关；向量化转换默认启用。构建的 muDNN 依赖仍需显式选项。
输入缓存未显示跨模型稳定收益，因此推荐先启用 SDPA + QKV，缓存单独评估。

## 正确性与限制

- CTest 18/18通过，包含非连续转换、真实16头单/双摄像头 SDPA、Graph 重放和原有算子测试。
- 完整推理入口覆盖两类模型各自 tokenizer、43/42文本token、480×640 PNG、相机顺序、状态处理及 F32/F16 激活。F32 激活对 CPU 参考的 relative_peak 为0.1115%/0.1272%，重复漂移0。
- 合成输入 F32 激活对原始 MUSA F32 参考 relative_peak 为0.0888%/0.1308%；对本轮 F16权重/F32激活基线为0.3615%/0.06356%。门槛0.5%，定义 max(abs(new-ref))/max(abs(ref))，不是逐元素相对误差。
- 变图像、文本、状态、噪声及同一16-token长度桶检查通过；返回原输入后重复漂移0。关闭裁剪诊断的生产分配验证也已通过（普通/同桶两组），见 additional-summary.json。
- 裁剪算法仍为稳定 topk；GPU结果与同一分数的CPU稳定topk一致。低精度视觉计算改变部分分数，24次图像比较有6次选中集合变化，最多替换1个patch；未承诺逐位等价。
- 两模型均捕获3个Graph；最后一次实例化之后各观察到7次GraphLaunch、0次直接KernelLaunch。原始API轨迹见 trace-*/，汇总见 summary-graph-traces.json。
- F16激活的裁剪模型在初次跨精度对照中出现0.60625%差异，超过对本轮F32激活基线的门槛，记录保留于 final-f16/。不能因对原始MUSA F32误差更小就忽略该失败；暂不推荐切换F16激活。同精度对照 final-f16-matched/ 的差异为0.70068%，也未通过。旧F16路径对原始MUSA F32参考为0.52998%，本身已超过本轮0.5%门槛；最终F16对该参考为0.17120%。这些不同参考的结果均保留，不据此宣称F16方案验收通过。
- 关闭SDPA后的回退两模型均通过，动作与本轮基线逐元素一致；3样本均值651.521/1373.482ms，见 fallback/。
- 这是有限输入下的数值与性能验收，未进行机器人实机任务成功率测试。

## 编译、启用与回退

在服务器仓库根目录执行；复用现有 GGUF，无需重新转换，两种 checkpoint 由现有 run_pi05.py 自动读取配置。

```bash
BUILD_DIR=$PWD/build-musa-official bash scripts/build_musa.sh -DVLA_MUSA_MUDNN_ATTN=ON
export VLA_LIBRARY=$PWD/build-musa-official/libvla.so
export VLA_MUSA_VISION_SDPA=1
export VLA_PI05_VISION_QKV=1
unset VLA_PI05_INPUT_CACHE
# 在原有 scripts/run_pi05.py 命令中使用：
# --weight-dtype f16 --act-dtype f32 --flash-attn --warmup 3
# 两种模型分别传入各自 /home/skysi/VLA/models/<模型目录>/gguf/model.gguf
```

需要测试缓存时加 VLA_PI05_INPUT_CACHE=1。SDPA 回退请 unset VLA_MUSA_VISION_SDPA；当前该开关按是否存在判断，设为0仍启用。
QKV 和缓存可 unset 或设为0。设置 VLA_MUSA_NO_VECTOR_PACK=1 可回退普通布局转换。
全部回到本轮起点：unset 三个正向开关并设置 VLA_MUSA_NO_VECTOR_PACK=1，保留已有三段Graph和FA。
无需使用 GGML_CUDA_DISABLE_GRAPHS；它只用于无Graph诊断。
编译选项默认OFF，库不可用的构建仍可使用通用 Attention；当前ON构建必须能加载SDK的 muDNN 依赖。
此专用 SDPA 仅在本机M1000与对应库验证，不推广到其他架构/库版本。

## 后续优先项

1. head_dim256 的前缀/动作 Attention 专用MUSA内核或受支持的库实现；当前占剩余时间较多，不能直接套用MP31专用MATE。
2. GemmEx/Lt输出的 bias、GELU、residual epilogue融合：本轮只完成QKV合并，未实现这些输出融合。
3. 视觉72维 SDPA 在修复独立描述符后重新测试无填充布局，减少128维padding成本；BF16路径尚未评估。
4. 内存方面继续减少视觉边界同步；mapped-host零拷贝仍未实现，必须与pinned复制测量对照。
5. 输入缓存仅为可选实验；更多真实输入、长期重放及实机闭环验证后再决定是否默认启用。

自动审批曾拒绝在交错复测前将实验开关和构建依赖改为默认启用；本轮保留显式选择，未绕过该限制。
