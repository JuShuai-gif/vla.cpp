# 01 热点与库评估

源码起点 6543803。实际测量配置：F16 权重、F32 逻辑激活、FlashAttention 开启，2 张合成 224×224 图像、6 个文本 token、4 CPU 线程、performance 电源模式。
两模型分别保留 3/10 去噪步、chunk50 和各自视觉 token 规则。

## 文件

- baseline/：预热3次、采样5次的普通推理；与原始 MUSA F32 参考比较。
- baseline/*/nodes.json 与 shapes.json：图构建时采集，不在稳态计时内输出。
- node-profile/：msys 节点模式；原始 msys-rep 位于 /home/skysi/VLA/official-node-traces-20261102/。
- event-profile/：VLA_MUSA_PROFILE_OPS=1 GGML_CUDA_DISABLE_GRAPHS=1，设备事件逐算子计时。每个算子同步，包含启动/诊断影响，不能冒充普通 Graph 延迟。
- event-hotspots.json：最后一次推理的事件聚合。
- lt/：每种形状独立进程、3 次预热、10 次事件均值、候选与 GemmEx 对照、Graph 捕获/重放误差。
- mcu-gemm.log：M=2560,N=50,K=1024 的代表性 GEMM；使用 mcu --dump-mode normal -k regex:gemmex。Profiler 下的微基准 wall/event 时间失真，不作性能对比。
- sdpa/：muDNN 能力与正确性微测试；probe_sdpa.cpp 为可复现源码。

## 有效发现及限制

1. 逐算子事件显示前缀大 MLP、动作 Attention、视觉 Attention 和视觉布局转换值得优先优化。
2. 完整模型视觉 F32→F16 CPY 的诊断累计约129.8ms，裁剪模型约65.6ms。专用向量化转换随后得到整模型收益，两种输出与基线一致。
3. mcu 能正常采集代表性 GEMM。报告包含 242 registers/thread、约24 KiB静态共享内存和执行利用率；这是单一 kernel 的样本，不推广为全模型利用率。
4. L2 计数器可报告流量，与 runtime 的 l2CacheSize=0 不矛盾；后者不能作为“没有物理 L2”的结论。
5. muBLASLt 增加 workspace 没增加候选，当前这组官方库/形状没有测到收益。不会为采用新 API 而替换更快的现有路径。
6. muDNN 的 head_dim256 当前不可用；视觉72维通过微测试不代表完整策略精度已经验证。保留通用 Attention 回退。
7. 构建诊断时遇到 cudaEventCreate/ElapsedTime 没有 MUSA 别名，已改用 musaEventCreate/ElapsedTime；失败和重试日志保留。

复现编译命令：
- Lt：/usr/local/musa/bin/clang++ -O2 -std=c++17 probe_lt.cpp -I/usr/local/musa/include -L/usr/local/musa/lib -Wl,-rpath,/usr/local/musa/lib -lmusart -lmublas -lmublasLt -lmusa -o /tmp/pi05-probe-lt
- SDPA：同上 probe_sdpa.cpp，链接 -lmusart -lmudnn -lmublasLt -lmusa，添加 -Wl,-rpath-link,/usr/local/musa/lib。
- 库探针运行设置 LD_LIBRARY_PATH=/usr/local/musa/lib。生产默认路径不因库探针而改变。
