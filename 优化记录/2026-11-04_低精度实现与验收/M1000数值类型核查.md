# M1000数值运算类型：官方规格与本机检查

环境：M1000 / compute capability 2.2 / mp_22 / warpSize128 / MUSA SDK5.1.0。
本次类型探针不是吞吐基准；成功只证明该形状可编译、运行且输出正确。

| 路径 | 本机结果 | 依据 |
| --- | --- | --- |
| FP32普通计算 | 已在现有推理与原生回归使用 | 原生39项测试 |
| FP16 × FP16 → FP32 | 1024项全正确 | wmma-type-f16-f16-f32-run-v2.txt |
| BF16 × BF16 → FP32 | 1024项全正确 | wmma-type-bf16-bf16-f32-run-v2.txt |
| TF32 × TF32 → FP32 | 1024项全正确 | wmma-type-tf32-f32-run-v2.txt |
| INT8 × INT8 → INT32 | 1024项全正确 | wmma-type-s8-s8-s32-run-v2.txt |
| 普通muBLAS INT8 GemmEx | 已测试调用返回NOT_SUPPORTED | row-mublas-not-supported.txt |
| 普通muDNN MatMul INT8/QINT8 | INT8→INT32/FLOAT返回NOT_SUPPORTED；QINT8组合INVALID_PARAMETER，TENSOR/SCALAR相同 | mudnn-int8-contract-probe-with-env.txt |
| INT8 × FP16 → FP32 WMMA | 正确补足satf参数后，mp_22编译后端不能选择该intrinsic，退出70 | wmma-type-s8-f16-f32-build-v3.txt |
| FP8 E4M3 WMMA | mp_22编译后端不能选择该intrinsic，退出70 | wmma-type-fp8-e4m3-f32-build-v2.txt |
| INT4/Q4、Q5 | 现有packed权重计算已测试；未证明原生INT4/INT5矩阵指令 | 不能把存储位宽当作矩阵单元输入能力 |

WMMA首次构建漏了MUSA语言/头文件参数，v1全部失败属于构建命令错误，不用于类型结论。
v2修正为clang++ -x musa -mtgpu --cuda-gpu-arch=mp_22。混合INT8×FP16在v2缺省satf参数不适用，
v3显式补足false后仍是后端不支持该intrinsic；不将首次签名错误当作硬件证据。
muDNN探针首次缺少LD_LIBRARY_PATH导致加载失败；with-env记录才是实际设备调用。
探针exit0仅表示没有已执行计算的数值错误；八种muDNN组合均未执行成功，不能按exit0记为支持。

官方资料（2026-11-04核查）：

- https://docs.mthreads.com/e300/version-1.6.0/e300-doc-online/product_overview/
  M1000所在E300模组的GPU标称FP16 12TFLOPS、INT8 24TOPS，条件为1.5GHz；
  50TOPS是融合GPU/NPU算力，不是当前GPU推理单独可用的算力。未据此推算本机实测频率。
- https://docs.mthreads.com/vllm-musa-m1000/vllm-musa-m1000-doc-online/AIModule/AIModule1.4.1%2Bvllm1.4.2/performance/
  官方M1000推理栈列出BF16与GPTQ INT4（W4A16）模型；这是软件部署支持，
  不能推出原生INT4×INT4硬件乘法或本项目可直接复用。
- https://docs.mthreads.com/musa-sdk/version-5.2.0/programming_guide/musa_cpp_syntax/math_functions_and_low_precision_types/
  官方明确要求把类型声明、矩阵输入约束、目标硬件与布局/转换成本分开检查。
  此文是5.2版，不能覆盖本机5.1的实测结果。

当前慢的原因与下一步：

Q8/Q4/Q5首先是整数权重加浮点scale的存储格式。当前正确的ggml MMQ使用DP4A，
真实前缀GateUp矩阵远慢于FP16 BLAS；quant_route=blas则每个GEMM反复解码到F16，
并未使用INT8 Tensor运算。手写W8A8 WMMA虽然正确，现有tile/预打包原型也尚未胜过FP16 BLAS。
因此后续应围绕已验证的INT8×INT8→INT32矩阵路径改善数据搬运、tile复用与动态激活量化融合，
只有单消费链更快后才接入整模型。不能再从位宽直接推断必然加速；
仍须每时刻7维action相对原BF16余弦≥0.999，并实际通过延迟门槛。
