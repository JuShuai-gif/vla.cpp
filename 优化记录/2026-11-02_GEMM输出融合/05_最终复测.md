# 最终复测与验收

M1000/MP22，SDK/编译器/驱动见环境.json。performance 电源模式、4 CPU threads、F16 权重/F32 激活、FlashAttention、视觉 SDPA/QKV 开启，输入缓存关闭。剪枝使用 fused-denoise，完整使用 fused-all。本轮候选开启 VLA_MUSA_VISION_EPILOGUE=all，基线取消该选项。chunk50、去噪步数 3/10 不变。

## 常规稳态性能

每组预热 3 次，按基线/候选/候选/基线交错，每轮 15 样本，共 30 样本/模型/方案；GPU 串行、相同运行库二进制。输入为两张 224×224 合成图、6 个文本 token。不能将它等同于真实相机到机器人执行的延迟。

## 正确性与边界

- 20/20 CTest；12 种随机 F32 输入形状对原 MUSA 链 max_abs=0，CPU 公式参考误差门槛为 2e-6，另检查超出网格尺寸的回退。
- 两模型、普通/16-token 桶、三组图像/文本/状态/噪声：与上轮基线全部 max_abs=0，重复漂移 0。
- 完整入口使用 480×640 原图、43/42 tokens、各自相机顺序和状态归一化；F32/F16 共 4 组输出与上轮完全一致。F32 对 CPU 参考相对峰值差为 0.139151%/0.031207%；F16 为 0.098092%/0.042962%。推荐与性能测量仍为 F32 激活。
- 常规/分段复测输出对本轮基线全部 max_abs=0；对原 MUSA F32 参考差异为 0.060063%/0.044712%，未放宽 0.5% 门槛。
- 每模型 3 个 Graph；最后一次实例化后的窗口有 7 次 GraphLaunch、0 次直接 kernel launch。窗口含收尾，不用于推断纯稳态同步次数。
- 归档.py核对最终运行库 SHA256 和源代码差异与性能快照一致。

采用独立 bias+GELU、bias+残差融合，矩阵乘仍走原库路径。Lt epilogue 的实测性能较差且 batch=2 当前配置误差约 98%，未采用。初版完整入口误差虽通过但约 0.44%，进一步定位编译差异后恢复与原路径一致；失败和探索记录均保留。

无新增专用工作区；未单独测量 ggml allocator 峰值。没有改变层数、保留 token 数、去噪步数或量化到 FP4。真实机器人成功率尚未测试，不宣称全局最优。

原始 JSON/命令、gzip 日志/节点清单/源码差异随 Git 归档。动作数组与 msys 大文件保留服务器路径/SHA256，见外部产物清单.json。不向 Mac 同步。
