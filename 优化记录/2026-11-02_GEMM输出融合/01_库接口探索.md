# muBLASLt 输出融合探测

本机 SDK 5.1.1 的 mublasLt.h 声明了 EPILOGUE_BIAS、EPILOGUE_GELU_BIAS、BIAS_DATA_TYPE 和 BIAS_BATCH_STRIDE。源码为 probe_lt_epilogue.cpp，运行脚本为 run_lt.py。官方 muBLASLt 开发手册链接已在此前调研记录中保存；本轮在线访问超时，接口参数按本机 SDK 头文件核对。

选择视觉投影和 FFN 的 1152/4304 宽度、256 tokens、batch 1/2；F16 输入，FP32 累加/输出。workspace 0/8/32/64 MiB，各返回 1 个候选（相同算法去重）。最终探测基线包含 GemmEx + 独立 bias 或 bias/GELU 后处理，候选为 Lt 融合输出；事件计时，各 3 次预热、10 次测量。这是微基准，不是模型端到端性能。

所有 batch=2 的候选误差都约 98%，显式设置 bias batch stride=0 后仍未通过。该结论限于当前 SDK、硬件和参数配置，不能泛化为整个 Lt 库不支持批处理。batch=1 的 bias 数值一致，GELU 与现有 tanh 公式并非逐位相同。准确耗时和误差见 lt/summary.json。由于当前双相机精度未通过，且单相机没有明显性能理由替换现有路径，本轮不将 Lt epilogue 接入模型。

过程记录：
- lt-initial 为第一次探测：基线只有 GEMM，未包含后处理，不作为公平性能对比。
- lt-second 为中间探测：结果结构未清零，不能可靠读取 heuristic.state；改为零初始化后重测，最终 lt 目录为有效结果。
- 首次临时构建缺少 include 路径，第二次误用了 driver 库 musa 而不是 runtime 库 musart；run_lt.py 已固定 include、musart 和 rpath。
