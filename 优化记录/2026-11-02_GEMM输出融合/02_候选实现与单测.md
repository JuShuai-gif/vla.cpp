# 初版候选实现与单测

本页记录初版。最终数值一致性修正见 [迭代记录](04_数值一致性迭代.md)。

复用现有 fused_bias_gelu、fused_bias_res 节点及 CPU 回退。在 MUSA stream 上分别执行 bias+tanh GELU、residual+(GEMM output+bias)；矩阵乘仍使用现有 GemmEx 路径，F16 输入和 FP32 累加不变。这是 GEMM 后处理的逐元素融合，未声称把自定义代码插入 muBLAS 内部。

环境开关 VLA_MUSA_VISION_EPILOGUE=gelu / residual / all，未设置时沿用原路径。覆盖视觉编码器的两次残差及 FFN 激活，保留单/双相机维度和剪枝层注意力分数输出。默认仍关闭。

最初单测用 ggml CPU 的 GELU 链作严格参考，出现 9.1e-5 归一化偏差，GPU 原链和融合核则通过。核对源码发现 ggml CPU 启用 GGML_GELU_FP16 查表。最终严格参考采用现有 CPU fused 回调的 F32 tanh 公式，并与 MUSA 原始算子链分别比较，门槛保持 2e-6，没有放宽模型 0.5% 门槛。保留 unit-initial.log。

最终测试包含宽度 33/1152/4304、序列 17/256、batch 1/2，共 12 种形状；检查前三轮输出及额外 5 次 Graph 执行。已通过，见 unit.log。实现用二维行/列网格，避免对每个元素执行 64 位取模。

边界保护：二维网格的行数大于 65535 或列宽无法安全放入 int 时，MUSA supports 返回 false，走既有回退；新增了不分配巨量缓冲的支持性检查。最终 CTest 全部 20 项通过。

按中间张量大小估算，每个视觉 block 删除两个 1152×256 的 bias 临时张量读写和一个 4304×256 的 GELU 输入临时读写。剪枝模型 15 层×2 相机，完整模型 27 层×2 相机，分别减少约 387.19 / 696.94 MiB 的逻辑全局内存读写。该数字是张量级估算，不是硬件 DRAM 带宽测量，也不代表减少了等量主机到设备拷贝。没有增加专用工作区。

这里的“没有增加专用工作区”只说明未新增独立分配；ggml allocator 管理的图缓冲可能变化，allocator 峰值本轮没有单独测量。
